Why the current app feels cold

It surfaces the plumbing, not the intent

The architecture is sound — an append-only event log, everything a projection of it. But that engineering truth leaked into the front door. The redesign keeps the machinery and changes what you stand in front of.

✕ The machine is the interface

Seven peer tabs — Activity, Runs, Work items, Workflows, Agent run, History, Events — and the home screen is the raw event feed. You navigate tables, not work.

✓ One thing you follow

A single object — the brief — carried from “what do you want done?” all the way to a landed change. Everything else becomes detail you open when you want it.

✕ Jargon as the vocabulary

Personas, pass-criteria, gates, infra templates, iteration budgets. Correct terms — but they ask you to think like the scheduler that runs them.

✓ Plain language you already own

Reviewers. “Done means…”. Your checkpoints. An isolated workspace. Same power, described the way you'd brief a trusted engineer.

Same engine, humane words

The vocabulary shift

None of this discards the architecture. It renames the front-of-house so you think about your work, not the scheduler. These are proposals — the terms are the cheapest thing to change and the highest-leverage.

Today's termProposedWhy
Work item→BriefThe thing you want done, not a row in a table.
Workflow→ApproachHow this work gets tackled — read as steps, not a definition.
Persona→Reviewer / ImplementerA role you'd recognise on a team.
Pass criteria→“Done means…”Verification authored as an outcome.
Human gate→CheckpointA place you chose to hold the reins.
Run→FlightOne commissioned brief, in motion.
Infra template→Isolated workspaceWorktree + containers, framed as safety.
Event log / History→The storyThe same truth, told as a journey.
On these mockups

What this is: a design of the journey and interactions, not a component spec — deliberately unconstrained by the current UI. The example brief (API rate-limiting) is illustrative. What it preserves: the event-sourced core, spec versioning, isolated worktrees, personas/criteria/gates, and the full audit trail. Everything shown is a reframing of the front-of-house over the machinery you've already built. Open calls for you: the naming (Brief / Approach / Flight) is a proposal; whether the first-run should auto-draft an approach from the prompt (an agent proposing stages) or always start from a saved template; and whether “right now / context pressure” lives per-flight or also in a cross-flight overview for when several are airborne at once.
